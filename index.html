PROJECT PLANNING

This section provides access to the project plan and weekly snapshots showing how planning developed over time.

Evolution of plan throughout project

Our initial plan established the main stages of the project, beginning with customer requirements and the selection of a game engine, followed by requirements specification, architectural design and implementation. We prioritised early activities such as the customer meeting, requirements work and setting up the GitHub repository because these provided the foundation for later development.

As the project progressed, the plan was adapted to accommodate the iterative nature of our design and implementation. Although we initially intended to complete the requirements and architecture stages before implementation, these activities overlapped. Coding began while the UML diagrams were still being refined. This allowed implementation to progress without waiting for every design detail to be finalised, while the diagrams could continue to reflect decisions made during development. We were able to follow our plan of using an iterative development method this way.

The plan was also extended to include specific implementation tasks as the game developed. These included the inventory, restart function and instructions screen. Breaking implementation down into individual features made the work more manageable and allowed tasks to be allocated and tracked separately. We also added website-related work, including publishing the project plan and making the assessment materials accessible.

Overall, our plan developed from an initial sequence of broad project stages into a more detailed list of implementation and documentation tasks. The way the plan developed reflects our iterative design methodology - as the code, UML diagrams and other aspects of the project developed, we edited the plan to accommodate for our increasing tasks. We retained the original emphasis on requirements and architecture, but allowed overlapping activities where this was practical.
